
there is a useful thing called a 'representative_point'


>>> import shapely
>>> line = shapely.LineString([(1,1),(2,2),(4,4)])
>>> line.centroid
<POINT (2.5 2.5)>
>>> line.representative_point()
<POINT (2 2)>
>>> 

shapely has coords
>>> line.coords
<shapely.coords.CoordinateSequence object at 0x10c755550>


>>> import geopandas as gpd
>>> LS = gpd.GeoSeries(line)
>>> 

>>> LS.get_geometry(0)
0    LINESTRING (1 1, 2 2, 4 4)
dtype: geometry
>>> LS.get_geometry(1)
0    None
dtype: geometry

>>> LS.representative_point()
0    POINT (2 2)
dtype: geometry
>>> LS.centroid
0    POINT (2.5 2.5)
dtype: geometry


sometimes representative_point() gives a point

and sometimes:
rp is a shapely.coords.CoordinateSequence object!

there may be more than one so
rep_point[0]

as a shapely object, it has a coords attribute

https://github.com/shapely/shapely/issues/984
so we want
t = rep_point[0].coords[:][0]

and then can do
x,y,_ = t

why so complicated?
what difference from centroid?

actually, if rp is a CoordinateSequence it's easier to do:
list(rp)


rp can also be a series!

import geopandas as gpd
from shapely.geometry import Point

gs = gpd.GeoSeries(
    [Point(1,1), Point(2,2), Point(3,3)])

>>> rp = gs.representative_point()
>>> 
>>> type(rep_point)
<class 'geopandas.geoseries.GeoSeries'>
>>>



>>> t = rep_point[0].coords[:][0]
>>> t
(1.0, 1.0)
>>> 
>>> type(rep_point[0])
<class 'shapely.geometry.point.Point'>
>>> type(rep_point[0].coords)
<class 'shapely.coords.CoordinateSequence'>
>>> type(rep_point[0].coords[:])
<class 'list'>
>>> type(rep_point[0].coords[:][0])
<class 'tuple'>
>>>
